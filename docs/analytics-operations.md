# Google Analytics 4 運用ガイド

Version 1.0　更新日：2026年8月18日

## 1. この文書の目的

外山建設公式サイトのGoogle Analytics 4（以下「GA4」）の設定・確認方法と、Cookie等に関する運用方針を記録します。

このサイトで最も知りたいのは、単なるアクセス数ではなく、次の点です。

- どのくらいの人が採用ページを見たか
- 採用ページを見た人が、応募・相談ボタンまで進んだか
- LINE通話、LINEチャット、メールのどれが使われたか
- Google検索、直接アクセス、SNS等のどこから来たか

## 2. 各サービスの役割

| サービス              | 役割                                                    |
| --------------------- | ------------------------------------------------------- |
| GA4                   | 閲覧ページ、流入元、計測対象のクリックを確認する        |
| Google Search Console | Google検索での表示回数、クリック数、検索語句を確認する  |
| Cloudflare Pages      | サイトを配信し、GA4測定IDをProduction環境変数で管理する |
| GitHub                | サイトのコードと運用文書を管理する                      |

Cloudflare PagesのProduction branchは `main` です。`main` へのマージ後、本番デプロイが自動実行されます。

GA4測定IDは、Cloudflare PagesのProduction環境変数で次の名前で管理します。リポジトリ内に本番の値は保存しません。

```text
NEXT_PUBLIC_GA_MEASUREMENT_ID
```

## 3. 現在計測している内容

GA4の標準機能で、次の内容を計測します。

- ページの表示回数
- 訪問者数とセッション数
- 閲覧されたページ
- 流入元・参照元
- 端末種類やブラウザ等のおおまかな利用環境

外山建設サイト独自のクリックイベントは次の通りです。

| イベント名            | 計測する操作                               |
| --------------------- | ------------------------------------------ |
| `line_call_click`     | LINE通話ボタンのクリック                   |
| `line_chat_click`     | LINEチャット・友だち追加ボタンのクリック   |
| `email_click`         | メールリンクのクリック                     |
| `recruit_page_click`  | トップ・会社案内から採用ページへの移動     |
| `recruit_apply_click` | 採用ページ内の応募欄へ進むボタンのクリック |

イベントには補助情報として、次の値を付けています。

| パラメータ  | 内容                                                     |
| ----------- | -------------------------------------------------------- |
| `page`      | `contact` または `recruit`。工事相談側と採用側を区別する |
| `link_text` | 押されたリンクの表示文字                                 |

### 計測値の限界

- ボタンのクリックは「相談・応募しようとした」ことを示し、実際の送信・通話成立を保証しません。
- PCに表示したQRコードをスマートフォンで読み取った行動は、サイト内のクリックではないため計測できません。
- Cookieの無効化、広告ブロッカー、ブラウザのプライバシー機能等により、すべての訪問を計測できるわけではありません。
- 社内閲覧や自分の動作確認も、除外設定をしない限り数値に含まれます。

## 4. まず行うGA4の設定

GA4の左下にある「管理」から、次を確認します。画面名はGoogleの更新により少し変わることがあります。

### Google Signalsと広告パーソナライズ

1. 「管理」を開く
2. 「データの収集と修正」の「データ収集」を開く
3. Google Signalsが無効であることを確認する
4. 広告パーソナライズをすべての地域で無効にする
5. Google広告とは連携しない

### データ保持期間

1. 「管理」を開く
2. 「データの収集と修正」の「データ保持」を開く
3. 「イベントデータの保持」を `2か月` にする
4. 「新しいアクティビティでユーザーデータをリセット」をオフにする
5. 保存する

2か月にしても、標準的な集計レポートが2か月後にすべて見られなくなるわけではありません。主に「探索」で使う利用者・イベント単位の詳細データの保持期間です。

### 主要イベントの登録

イベントは、サイト上で実際に1回発生した後にGA4のイベント一覧へ表示されます。表示まで時間がかかる場合があります。

採用と問い合わせに直結する次のイベントは、GA4の「管理」→「データの表示」→「イベント」で「キーイベントとしてマーク」をオンにします。

- `line_call_click`
- `line_chat_click`
- `email_click`

`recruit_page_click` と `recruit_apply_click` は、応募前の途中行動として確認します。

## 5. 計測開始時の動作確認

1. Cloudflare PagesのProduction環境変数にGA4測定IDがあることを確認する
2. `main` の最新デプロイが成功していることを確認する
3. GA4で「レポート」→「リアルタイム」を開く
4. 別のタブまたはスマートフォンで `https://toyama-kensetsu.com` を開く
5. トップページから採用ページへ進む
6. 採用ページで応募欄へ進むボタンを押す
7. LINEチャットまたはLINE通話ボタンを押す
8. GA4のリアルタイムにアクセスとイベントが表示されるか確認する

データ収集の開始まで最大30分程度、通常のレポートへの反映には24〜48時間程度かかる場合があります。

## 6. GA4の基本用語

| 用語         | 意味                                                                                     |
| ------------ | ---------------------------------------------------------------------------------------- |
| ユーザー     | サイトを利用した人のおおよその数。正確な個人数ではなく、ブラウザやCookieを基にした推定値 |
| セッション   | 1回の訪問のまとまり。同じ人が日を変えて来ると別セッションになる                          |
| 表示回数     | ページが表示された回数。同じ人が何度見ても加算される                                     |
| イベント     | ページ表示やボタンクリックなど、サイト内で記録された行動                                 |
| キーイベント | 問い合わせに近い操作など、特に重要と決めたイベント                                       |
| 流入元       | Google検索、他サイト、直接アクセス等、訪問のきっかけ                                     |

## 7. 月に1回の確認方法

毎日確認する必要はありません。まずは月に1回、前月の数値を確認します。開始直後は比較対象がないため、数値の記録だけで構いません。

### サイト全体

GA4の「レポート」→「ライフサイクル」または「ビジネス目標」から確認します。表示されるメニュ名はGA4の設定によって異なります。

| 確認する数字             | おもな場所                                  | 何が分かるか                                 |
| ------------------------ | ------------------------------------------- | -------------------------------------------- |
| ユーザー数・セッション数 | 「ユーザー属性」「集客」                    | どのくらいの人が訪問したか                   |
| 流入元                   | 「集客」→「トラフィック獲得」               | Google検索、直接、他サイト等のどこから来たか |
| 閲覧ページ               | 「エンゲージメント」→「ページとスクリーン」 | トップ、会社案内、採用のどこが見られたか     |
| イベント数               | 「エンゲージメント」→「イベント」           | LINEやメール、採用導線のクリック数           |

### 採用の確認順序

1. 「ページとスクリーン」で `/recruit` の表示回数を確認する
2. 「イベント」で `recruit_page_click` を確認する
3. `recruit_apply_click` を確認する
4. `line_call_click`、`line_chat_click`、`email_click` を確認する
5. 実際に来た応募・相談数と照合する

例えば、次のように考えます。

```text
採用ページの閲覧：50回
応募欄へ進むクリック：10回
LINE・メールクリック：3回
実際の応募・相談：1件
```

この場合、採用ページまでは人が来ており、その一部が応募行動まで進んでいます。月1件程度の応募であっても、それだけでサイトが失敗しているとは判断しません。少なくとも2〜3か月の傾向を見ます。

### 工事相談の確認順序

1. トップページと会社案内ページの閲覧を確認する
2. `line_call_click`、`line_chat_click`、`email_click` を確認する
3. 実際の工事相談数と照合する

## 8. 月次記録のテンプレート

次の項目をメモや表計算ソフトに月ごとに記録します。

| 項目                   | 今月 | 前月 | メモ |
| ---------------------- | ---: | ---: | ---- |
| ユーザー数             |      |      |      |
| セッション数           |      |      |      |
| `/recruit` の表示回数  |      |      |      |
| `recruit_page_click`   |      |      |      |
| `recruit_apply_click`  |      |      |      |
| `line_call_click`      |      |      |      |
| `line_chat_click`      |      |      |      |
| `email_click`          |      |      |      |
| 実際の採用応募・相談数 |      |      |      |
| 実際の工事相談数       |      |      |      |

アクセス数が少ない月は、数件の差で割合が大きく変わります。単月の割合だけで判断せず、実際の問い合わせ内容も一緒に確認します。

## 9. データが表示されない場合

次の順に確認します。

1. Cloudflare Pagesの本番デプロイが成功しているか
2. Production環境変数の名前が `NEXT_PUBLIC_GA_MEASUREMENT_ID` になっているか
3. 環境変数設定後に再デプロイしたか
4. GA4で正しいプロパティを開いているか
5. 測定IDがCloudflareの値と一致しているか
6. 広告ブロッカーを無効にしたブラウザまたは別端末で確認したか
7. リアルタイム反映まで30分程度待ったか

## 10. Cookieとプライバシーの運用方針

### Cookieとは

Cookieは、ウェブサイトがブラウザに保存する小さなメモです。GA4は、同じブラウザからの訪問かどうかをおおまかに区別するため、`_ga` 等のCookieを使います。

これは名前や電話番号を保存するものではありませんが、閲覧行動の把握に使われるため、利用目的を公表して慎重に扱います。

### 現在の方針

- Cookie同意バナーは設置しない
- 主な対象地域は日本・新潟県央地域とする
- Google Signalsは無効にする
- 広告パーソナライズは無効にする
- Google広告とは連携しない
- GA4のデータ保持期間は2か月とする
- 氏名、電話番号、メールアドレス、LINEの会話内容、応募内容等をGA4へ送らない
- Google AnalyticsとCookie等の利用目的、収集する情報、無効化方法を `/privacy` で公表する
- Google公式のデータ利用説明へのリンクを `/privacy` に掲載する

### Cookie同意バナーを再検討する条件

次のいずれかを始める、または状況が変わるときは、GA4の設定やコードを変更する前にCookie同意バナーの必要性を再確認します。

- EU・英国等の海外向けに積極的な集客を始める
- Google広告を始める
- リターゲティング広告を始める
- Google Signalsを有効にする
- 広告パーソナライズを有効にする
- 会員情報、応募者情報、問い合わせ情報等とアクセス履歴を紐付ける
- 複数のサイトをまたいで利用者を追跡する
- Google Analytics以外の解析・広告サービスを追加する
- サイトの対象地域や事業内容が大きく変わる
- 関係法令、Googleの利用規約、プライバシーポリシーが変更される

Cookie同意バナーを設置しない現在の判断は、上記の運用条件を前提とします。条件が変わった場合は、必要に応じて専門家へ確認します。

## 12. 変更時のチェック

GA4、広告、Cookie、問い合わせ方法を変更するときは、次を同時に確認します。

- 計測コードとイベント名
- Cloudflare Pagesの環境変数
- GA4管理画面のプライバシー設定
- `/privacy` の記載
- 本文書の現在方針と再検討条件
- 動作確認とテスト
