# 非機能要件定義書

**プロジェクト**: 株式会社 外山建設 コーポレートサイト  
**技術スタック**: Next.js (SSG) / TypeScript / Tailwind CSS / Cloudflare Pages  
**バージョン**: v1.0  
**作成日**: 2026-06-09

---

## 前提

本サイトはサーバーサイド処理を持たない**静的サイト（SSG）**であり、Cloudflare Pages でホスティングする。
この前提から、以下の要件はそもそも発生しない。

| 一般的な非機能要件                          | 本サイトへの適用                     |
| ------------------------------------------- | ------------------------------------ |
| スループット（1秒あたりのリクエスト処理数） | 不要：Cloudflare CDN が自動で捌く    |
| 水平・垂直スケーリング                      | 不要：静的配信のためサーバー管理なし |
| DBのバックアップ・冗長化                    | 不要：DBを持たない                   |
| 認証・認可                                  | 不要：ログイン機能なし               |
| サーバーサイドの監査ログ                    | 不要：サーバー処理なし               |

## 1. パフォーマンス（Performance）

### 目標値

| 指標                              | 目標       | 計測ツール                      |
| --------------------------------- | ---------- | ------------------------------- |
| **LCP**（最大コンテンツ描画）     | 2.5 秒以内 | Lighthouse / PageSpeed Insights |
| **INP**（操作応答性）             | 200ms 以内 | Lighthouse / PageSpeed Insights |
| **CLS**（レイアウトずれ）         | 0.1 未満   | Lighthouse / PageSpeed Insights |
| **Lighthouse Performance スコア** | 75 以上    | Lighthouse                      |
| **ページ全体の転送サイズ**        | 1MB 以内   | Chrome DevTools                 |

> LCP / INP / CLS は Google の **Core Web Vitals** であり、検索順位にも影響する。

### 実装上の制約

- 画像は 1 枚 **200KB 以下**に圧縮してからコミットする（Squoosh 等で変換）
- 画像は必ず `next/image` の `<Image>` コンポーネントを使用し、自動最適化・遅延読み込みを有効にする
- ヒーロー背景など LCP に直結する画像には `priority` prop を付ける

```tsx
// LCP 対象画像には priority を付与
<Image src="/images/hero-bg.jpg" alt="..." priority />
```

## 2. 可用性（Availability）

### 目標稼働率

**99.9%**（年間ダウンタイム約 8.76 時間）

### 根拠

- Cloudflare Pages の実績稼働率は 99.99% 以上（SLA に準拠）
- 静的ホスティングのためアプリケーションサーバーの障害リスクがない
- メンテナンスウィンドウが不要（デプロイ中も旧バージョンが配信される）

### 障害発生時の対応

- GitHub の `main` ブランチが唯一の真実のソースであり、Cloudflare Pages から即時ロールバックが可能
- LINE・メールによる問い合わせ導線はサイト外のため、サイトダウン時も問い合わせ機能は影響を受けない

## 3. セキュリティ（Security）

### 実装必須事項

| 項目                     | 対応方法                                         | 理由                           |
| ------------------------ | ------------------------------------------------ | ------------------------------ |
| **HTTPS 強制**           | Cloudflare が自動付与                            | 通信の暗号化                   |
| **外部リンクの属性**     | `rel="noopener noreferrer"`                      | タブナビゲーション攻撃の防止   |
| **APIキーの管理**        | `.env.local` に記述、`.gitignore` でコミット除外 | Google Maps API キーの漏洩防止 |
| **セキュリティヘッダー** | `next.config.ts` または Cloudflare Pages で設定  | クリックジャッキング等の防止   |

### 推奨セキュリティヘッダー

```ts
// next.config.ts
const securityHeaders = [
  { key: "X-Frame-Options", value: "DENY" },
  { key: "X-Content-Type-Options", value: "nosniff" },
  { key: "Referrer-Policy", value: "strict-origin-when-cross-origin" },
];
```

### 本サイトに該当しないリスク

フォームなし → SQL インジェクション・CSRF・XSS（入力起点）のリスクなし  
ログイン機能なし → セッション乗っ取りのリスクなし  
個人情報の収集なし → 情報漏洩リスクが限定的

## 4. アクセシビリティ（Accessibility）

### 準拠レベル

**WCAG 2.1 レベル AA** を努力目標とする（必須要件ではなく、対応コストと照らして判断する）

### 実装要件

| 項目                    | 要件                                                                               |
| ----------------------- | ---------------------------------------------------------------------------------- |
| **カラーコントラスト**  | テキストと背景の比率 **4.5:1 以上**（メインカラー #1E3A5F と白の組み合わせは適合） |
| **代替テキスト**        | 全画像に適切な `alt` を設定（装飾目的の場合は `alt=""`）                           |
| **キーボード操作**      | Tab キーで全リンク・ボタンにアクセスできること                                     |
| **セマンティック HTML** | `<header>` `<nav>` `<main>` `<section>` `<footer>` を適切に使用                    |
| **見出し階層**          | `h1` → `h2` → `h3` の順序を守る（スキップしない）                                  |

## 5. SEO（Search Engine Optimization）

採用・問い合わせを促進するという目的から、検索流入は重要な非機能要件として扱う。

### 実装要件

| 項目             | 要件                                                                              |
| ---------------- | --------------------------------------------------------------------------------- |
| **メタタグ**     | 各ページに `title` と `description` を設定                                        |
| **OGP**          | SNS シェア時に社名・キャッチコピーが表示されるよう `og:title` / `og:image` を設定 |
| **構造化データ** | `LocalBusiness` スキーマを JSON-LD で設定（Google 検索での会社情報表示）          |
| **Sitemap**      | `sitemap.xml` を生成・公開                                                        |
| **robots.txt**   | クロールを許可する設定                                                            |

```tsx
// app/layout.tsx での metadata 例
export const metadata: Metadata = {
  title: "株式会社 外山建設 | 新潟県三条市の土木・外構工事",
  description: "新潟県県央地区を中心に土木・外構工事を手がける外山建設。お気軽にLINEまたはメールでご相談ください。",
  openGraph: { ... },
};
```

## 6. 対応ブラウザ・デバイス（Compatibility）

### 対応範囲

| カテゴリ           | 対象                                           |
| ------------------ | ---------------------------------------------- |
| **スマートフォン** | iOS Safari 16+、Android Chrome 最新2バージョン |
| **PC**             | Chrome / Firefox / Edge 最新2バージョン        |
| **非対応**         | Internet Explorer（全バージョン）              |

### レスポンシブ対応

モバイルファーストで設計する。想定閲覧比率はスマートフォン約8割・PC約2割。問い合わせ導線（LINE）はモバイルからのタップが主要動線のため、ボタンのタップ領域は **44px × 44px 以上**を確保する。

## 7. 保守性（Maintainability）

### コード品質の担保

| ツール                  | 役割                                      |
| ----------------------- | ----------------------------------------- |
| **ESLint**              | 静的解析・コーディング規則の強制          |
| **Prettier**            | フォーマットの統一                        |
| **Husky + lint-staged** | コミット前に ESLint / Prettier を自動実行 |
| **Vitest**              | コンポーネントの自動テスト                |

### 更新しやすさのための設計ルール

- 会社情報（住所・電話・LINE URL 等）は `src/constants/company.ts` のみに記述し、コンポーネントへのハードコードを禁止する
- コンポーネントは 1 ファイル 1 コンポーネントとし、影響範囲を局所化する

### デプロイフロー

```
開発 → git push (develop) → PR → main へマージ → Cloudflare Pages が自動ビルド・デプロイ
```

## 9. ログ・監視（Logging & Monitoring）

### 前提

本サイトはサーバーサイド処理を持たない静的サイトのため、以下は不要。

| 一般的なログ種別           | 本サイトへの適用             |
| -------------------------- | ---------------------------- |
| サーバーアクセスログ       | 不要：Cloudflare が自動保持  |
| アプリケーションエラーログ | 不要：サーバーサイド処理なし |
| DB クエリログ              | 不要：DB なし                |

### 9.1 アクセス解析

| ツール                       | 費用 | 設定箇所                                  |
| ---------------------------- | ---- | ----------------------------------------- |
| **Cloudflare Web Analytics** | 無料 | Cloudflare Pages ダッシュボードから有効化 |

- Cookie 不要かつプライバシーポリシー・同意バナー不要（Google Analytics と異なる）
- 計測対象：PV 数・ユニーク訪問者数・流入元・デバイス種別

### 9.2 コンバージョン計測

LINE・メールの各ボタンクリック数を `src/lib/analytics.ts` の `trackConversion()` で計測する。  
実装はサービス非依存の薄いラッパーとし、将来の解析ツール変更に対応できる構造とする。

| イベント名  | 発火条件                      | 対象ページ        |
| ----------- | ----------------------------- | ----------------- |
| `line_call` | LINE通話ボタンクリック        | contact / recruit |
| `line_add`  | 友だち追加ボタン・QR クリック | contact / recruit |
| `email`     | メールを送るボタンクリック    | contact / recruit |

```typescript
// src/lib/analytics.ts
trackConversion(method: 'line_call' | 'line_add' | 'email', page: 'contact' | 'recruit')
```

### 9.3 死活監視

| ツール          | 費用            | 通知方法   |
| --------------- | --------------- | ---------- |
| **UptimeRobot** | 無料（5分間隔） | メール通知 |

- 監視 URL：本番 URL のトップページ
- アラート先：`COMPANY.email` のアドレスに登録

### 9.4 パフォーマンス監視

Google Search Console の **Core Web Vitals レポート**を使用。サイト公開後すぐに登録すること。

### 実施タイミング

| #   | 対応                                                | タイミング         |
| --- | --------------------------------------------------- | ------------------ |
| 1   | コンバージョントラッキング実装（`trackConversion`） | 開発中（実装済み） |
| 2   | Cloudflare Web Analytics 有効化                     | 公開時             |
| 3   | UptimeRobot 登録                                    | 公開時             |
| 4   | Google Search Console 登録                          | 公開後1週間以内    |
